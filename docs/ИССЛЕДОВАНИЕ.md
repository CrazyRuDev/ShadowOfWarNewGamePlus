# Shadow of War: новая игра плюс — исследование сохранений

Цель: перенести в новую игру снаряжение, умения, очки умений, уровень, опыт и армию Немезиды
из сохранения пройденной игры.

## Шаг 1. Шифрование сохранений — разобрано

`sowsave.py` расшифровывает и зашифровывает `<id>_ShadowOfWar.sav`. Круговой прогон
(расшифровать → зашифровать) даёт файл, побайтно совпадающий с исходным.

```
python3 sowsave.py decrypt 096c2a9f_ShadowOfWar.sav save.bin
python3 sowsave.py encrypt save.bin 096c2a9f 096c2a9f_ShadowOfWar.sav
```

Формат (ShadowOfWar.exe 1.0.8874.0, чтение — `0x14119A3FD`, запись — `0x14052B1CC`):

| Смещение | Поле | Значение |
|---|---|---|
| 0 | magic | `SOM3` (старый вариант `SOM2` без идентификатора пользователя) |
| 4 | crc32 | CRC32 расшифрованных данных (функция `0x140505400`) |
| 8 | enc_size | размер зашифрованных данных |
| 12 | plain_size | размер расшифрованных данных |
| 16 | данные | AES-256-CBC (OpenSSL, NID 427), дополнение PKCS#7 |

- Ключ: строка `ad@210766@vac94Cd_?dVt5$alivjz$e`, в которую записываются байты CRC32
  (позиции 0x1A, 0x0B, 0x12, 0x11) и байты идентификатора пользователя (0x0A, 0x1E, 0x16, 0x02).
- IV: `yuwgb@oftv@gx$t3`.
- Идентификатор пользователя — шестнадцатеричный префикс имени файла сохранения
  (`096c2a9f_ShadowOfWar.sav` → `0x096c2a9f`), а не Steam ID.
- Не-Steam версии называют сохранение по имени компьютера (`DESKTOP-UI2I7KD_ShadowOfWar.sav`) и шифруют
  с идентификатором 0 (проверено на чужом сохранении). Движок пробует номер из имени, затем 0.

После изменения сохранения Steam Cloud может вернуть старую версию — перед проверкой
изменённого файла облачную синхронизацию для игры лучше отключить.

## Шаг 2. Структура расшифрованных данных — в работе

- Заголовок: `SAVE`, версия 2, размеры, номер сборки игры (8874), число 5.
- Данные разбиты на блоки с четырёхбуквенными метками (`INVA`, `QSTD`, `FORT`, `DIFF`,
  `IVPD`, `IVSH`, `PPDC`, `STOR`, …). У блока: метка, версия, размер.
- Почти все метки встречаются в трёх местах файла (около 0x150000, 0x1DE000, 0x21E000).
- Персонажи Немезиды обозначены строками вида `<хеш>_NPC_<номер>`.

Проверенные сохранения (оба — сборка 8874, `SAVE` версии 2):

| Сохранение | Префикс | Размер данных | Строк `_NPC_` | Блоки `FORT` |
|---|---|---|---|---|
| поздняя игра (2026) | `096c2a9f` | 2 285 332 | 537 | есть |
| после пролога (2020) | `0b572f33` | 1 298 557 | 0 | нет |

Префикс у сохранений разных лет разный, но расшифровка одинаково работает с префиксом из имени файла.

### Кодирование значений

Значения записаны токенами «байт типа + 4 байта»: `04 <int32>` — число, `00 <u32>` — идентификатор
(хеш имени поля или записи). Пример: `00 a1 75 f6 88 04 44 00 00 00` — запись `0x88F675A1`, первое значение 68.

### Найденные поля (сохранение поздней игры, проверено по экрану игры)

| Что | Где | Значение |
|---|---|---|
| Уровень Талиона − 1 | блок `PPDC`, запись `0x88F675A1`, 1-е число | 68 (в игре уровень 69) |
| Опыт внутри уровня | там же, 2-е число | 47 431 (порог 93 090 берётся из таблиц игры) |
| Мирианы на счету | `IVMG`, запись `PC_Mirian` (`0x23B603FB`) в списке запасов | 9 333 371 (подтверждено по экрану игры) |
| Неизвестный счётчик | поле `0x55D62C09` | 383 018 (+600 вместе с мирианами) |
| Число изученных навыков | несколько мест, например после поля `0x00000069` | 106 = 22+13+16+21+14+20 |

Около двадцати полей выросли на 1 между сохранениями — это счётчики статистики.

Свободные очки навыков — запись `SkillPoint` в таблице запасов IVMG (`0c 01 00 SkillPoint 04 <очки> 04 0 04 0`);
при нуле очков записи нет совсем (поэтому сначала казалось, что счётчика нет). В IVPD `SkillPoint 1` — только
признак «очки уже получали». Третье число в записи `PPDC` (1) при этом не изменилось.

### Устройство блоков

```
метка (4) | версия (u32) | размер (u32) | 0 (u32) | размер − 4 (u32) | содержимое
```

Пример `IVPD` из пролога: `IVPD`, версия 4, размер 169, затем `04 03` — три владельца,
`00 a1 75 f6 88` — владелец `0x88F675A1` (Талион), `04 0d` — 13 записей, далее записи
`00 <идентификатор> 04 <значение>`.

### Блок `IVPD` — разблокировки (навыки и др.)

Записи «идентификатор → значение», значение — уровень/признак (1 — изучено, 0 — нет, у
навыков престижа — ранг). Изучение «Престижа истории» (ранг 5 → 6) изменило записи
`0xBEE2E5C1` и `0x674B1938` (5 → 6); `0xBEE2E5C1` есть ещё во второй таблице около `0xB3C1`.

| Сохранение | Записей Талиона в `IVPD` |
|---|---|
| после пролога | 13 |
| поздняя игра | 484 |

### Блок `IVMG` — инвентарь (версия 43, ~83 КБ)

- В начале — длинный список `0c 01 00 <идентификатор> 04 1 04 0 04 0` (вероятно, открытые образцы предметов).
- Далее — экземпляры предметов: `0c 01 04 <номер экземпляра> 04 <уровень> 02 00 00 <образец> 00 …`,
  после чего идут остальные свойства (самоцветы, эффекты, прежний владелец — ещё не разобраны).
- В позднем сохранении 183 экземпляра. В игре по слотам 26 + 25 + 25 + 33 + 39 = 148, остальное — кольца и прочее.
- Номера экземпляров уникальны (1…1304), похоже, выдаются по порядку получения предметов.
- Характеристики (урон, здоровье и т. п.) в сохранении не хранятся — игра считает их сама.

**Список предметов**: заголовок `04 <число предметов>` (в последнем сохранении 187), затем записи предметов
подряд, сгруппированные по видам: мечи, кинжалы, луки, …, доспехи, маски/плащи, кольца. У первого предмета
нет ведущего `0c xx`.

**Легендарность определяется образцом**: у легендарного предмета образец уникален, обычные (от обычного до
высшего) делят общие образцы (например, `0xEF6923F3` — 9 разных обычных мечей). Число `04 0N` после образца —
не редкость. Проверено на мечах: 26 мечей (первые 26 записей, начиная с №1031) — 12 легендарных
(ур. 20, 56, 60, 60, 60, 60, 63, 64, 65, 67, 68, 70) и 14 обычных (59, 61, 62, 62, 63, 64, 66, 66, 66, 66, 67,
70, 71, 72) — совпадает с игрой.

**Запись предмета** (токены: `00` — 4-байтный идентификатор, `04` — int32, `05` — 8 байт, `0a` — float,
`0c`/`02`/`0f` — 1 байт). Легендарный Дробящий меч №144:

```
144 | 68 | 02:0 | #e5510559 (образец) | #a6889f21 | #0 | 0c:0 0c:1 |
3 | #b2ef071c #7d33cee7 #0f6ada36      ← список идентификаторов (у лука их 4)
0 | Q4e5fa4f593b2acb7 Qcd719f74c5f2229a ← два 8-байтных значения (вероятно, зерна случайных характеристик)
0f:0 | 02:6 | 0c:1 | #de49253a #0 #d7eb1bb0 | 575800379 | 0  ← прежний владелец
```

- Хвост `0c:1 #X #0 #Y <число> 0` есть только у предметов с прежним владельцем: у Доспехов возмездия
  и Маски Бессмертного (в игре без строки «Прежде снаряжением владел») его нет. #X/#Y, вероятно, имя и прозвище орка.
  Число (`0x2252xxxx` или `0xC2EFxxxx`) повторяется у разных орков — не личный идентификатор и не племя.
- У доспехов и маски ненулевой идентификатор стоит в третьем поле после образца, у оружия — во втором.
- Значение `02:N` (0…6) пока не объяснено.
- Названия, тексты эффектов, урон и цена продажи в записи не хранятся — игра берёт их по идентификаторам.
- Самоцветы в запись предмета не входят: вставка самоцвета в кинжал запись кинжала не изменила.

**Надетое снаряжение** — список `0c 01 04 <номер экземпляра>` (пустой слот — `0c 00`) ближе к концу `IVMG`
(смещение ~0x144A5 от начала блока). Проверено сменой меча:

| Позиция | Номер | Уровень | Образец | В игре |
|---|---|---|---|---|
| 2 | 144 → 1012 | 68 → 70 | `0xE5510559` → `0x4EF6EF5A` | Дробящий меч → Меч негодяя |
| 3 | 718 | 69 | `0xC2728578` | Кинжал войны, ур. 69 |
| 4 | 133 | 68 | `0xC7D48712` | Лук тайных искусств, ур. 68 |
| 13 | 685 | 68 | `0x1587A923` | Доспехи возмездия, ур. 68 |
| 14 | 179 | 68 | `0x2A5AB520` | Маска Бессмертного, ур. 68 |

Остальные позиции — предметы 1-го уровня (номера 28, 1, 1304, 577, 84) и номера, которых нет среди предметов
(1322–1324, после изменения 1326–1328; меняются при каждом изменении снаряжения). Где кольцо — пока не ясно.

**Самоцветы**: вставка зелёного самоцвета в кинжал добавила в `IVMG` 100 байт — новый экземпляр 1329
с образцом `0x2013CB02` (запись в начальном списке и запись экземпляра).

### Разделы файла

Сохранение содержит три внутренних раздела (метки `SAVE` после основного заголовка),
у каждого блоки повторяются. В позднем сохранении заполнены первый и второй, в прологе — только
первый. Вероятно, это основная кампания и кампании дополнений (владельцы `0xB9A737CB`,
`0xB9A737CC` встречаются рядом с Талионом).

Для поиска полей нужны пары сохранений, различающиеся одним действием
(например, до и после траты одного очка умения), и сохранение начала новой игры.

## Архивы игры `.arch06` — формат разобран

Контейнер `LTAR` версии 4 (`tools/ltar.py`):

```
'LTAR' | версия 4 | размер таблицы имён | число папок | число файлов | … (до 0x30)
таблица имён (строки через \0)
файлы, по 30 байт: смещение имени u32 | смещение данных u64 | сжатый размер u64 | размер u64 | флаги u16
папки, по 16 байт: смещение имени | подпапка | следующая | число файлов (файлы идут по порядку папок)
```

Данные файла — блоки `сжатый размер u32 | размер u32 | данные` (до 64 КБ распакованных), выровненные
на 4 байта от начала файла (заполнитель `X`). Если размеры равны — блок не сжат, иначе это Oodle:
`8C 06` — Kraken (распаковывается [ooz](https://github.com/powzix/ooz), собранным как `libooz.so`),
`8C 02` — другой алгоритм Oodle, пока не поддерживается (встречается в мелких файлах).

`tools/list_arch.ps1` — выводит список файлов всех архивов игры (читает только заголовки).

Нужные для NG+ файлы (по списку содержимого всех архивов, 488 763 файла):
- `database\game\game.gamedb` (~58 МБ) — игровая база; версии в `hotchunk`, `Patch_01`…`Patch_04`.
- `database\string\<язык>\string.strdb` (~7 МБ) — тексты; русский — `ruru`, версии в `hotchunk`, `Patch_01`, `Patch_02`.

`tools/extract_arch.ps1` копирует эти файлы из архивов в сжатом виде (без распаковки) и упаковывает в zip.

### Тексты `string.strdb` — формат разобран (`tools/strdb.py`)

```
'SKDB' | версия 9 | размер заголовка 0x1C | число строк | 0 | длина текста (в символах UTF-16) | 0
записи по 8 байт: ключ u32 | смещение строки (в символах от начала текста)   — отсортированы по ключу
текст: строки UTF-16LE, каждая заканчивается нулём
```

Актуальная русская версия — в `hotchunk.arch06` (68 547 строк; в `Patch_02` — 63 512, часть блоков там
в неподдерживаемом сжатии `8C 02`). Пример: ключ `0x462F7E8E` — «Дробящий меч», `0x462F7E84` — его особое
свойство («Каждая атака глефой вызывает взрыв»), `0x4CDB20F5`/`0x4CDB20FF` — описание и название с именем
прежнего владельца. У пар «название/описание» ключи отличаются только последним байтом (`xor 0x0A` = `N`/`D`),
так что ключи похожи на FNV-1 от имён вида `…_N`/`…_D`, но сами имена в файлах игры не найдены.

### База `game.gamedb` — связь с сохранением найдена

**Идентификаторы в сохранении — хеш имени записи базы**, та же функция даёт ключи текстов `string.strdb`
(exe `0x140423E70`): `h = h * 0x397 + вес(символ)`, начальное `h = 0`; вес — таблица exe `0x141DB50D0`
(буквы без учёта регистра 1…26, цифры 27…36, знаки — свои коды). Примеры:

| Идентификатор | Запись базы | В игре |
|---|---|---|
| `0xE5510559` | `Primary_1Sword_5Lgnd_Machine` | Дробящий меч |
| `0x4EF6EF5A` | `Primary_1Sword_5Lgnd_Outlaw` | Меч Негодяя |
| `0x88F675A1` | `SinglePlayer` | Талион (владелец записей `PPDC`, `IVPD`) |
| `0x4CDB20FF` | `UI_1Sword_5Lgnd_Machine_N` | текст «Дробящий меч ({1!ls})» |

Устройство `GADB` (версия 17):
- `0x08` — размер пула строк, пул начинается с `0x47`; записи ссылаются на строки смещением в пуле.
- Заголовок категории: имя, тип, путь `\…\gdb.category06`, 0, число записей, хеш имени (категории
  отсортированы по хешу). Затем записи: имя, слово типа, слово `0x08xxxxxx`, поля.
- Ссылка на другую запись — `(категория << 20) | номер записи в категории`, «нет значения» — `0xFFFFFFFF`.
- Навык: запись `Inventory/Items` `PS_<навык>_UNLOCK` ссылается на `Inventory/UIItemData` `PSUID_…`,
  а та — на ключи текстов `PSN_Krak_…` (название) и `PSD_Krak_…` (описание).
- Названия предметов: легендарные — текст `UI_<образец без Primary_>_N`, комплект назгулов — `UI_<свойство
  комплекта>_N`, прочие — `UI_Nem_Name_<запись NG_ без NG_ и редкости>`; свойства — `UI_<слот>_N_<свойство>`
  и `UI_<…_SetProp_…>_D`; прозвище прежнего владельца — `Orc_Title_<запись Role_ без Role_>`.

`tools/sowinfo.py` выводит по сохранению уровень, мирианы, изученные навыки (106 — совпадает с игрой),
надетое снаряжение и весь инвентарь с русскими названиями и свойствами.

Поправка к таблице надетого снаряжения выше: №179 — Доспехи возмездия (`Primary_4Armor_5Lgnd_Vendetta`),
№685 — Маска Бессмертного (`Primary_5Cape_5Lgnd_Ringwraith_Nazgul_Generic`, слот плаща). Экземпляр №1329,
появившийся после вставки самоцвета, по образцу — `Rhovanion_Scabbard` (ножны), а не самоцвет.

### Список запасов в начале `IVMG`

Записи `0c 01 00 <запись> 04 <количество> 04 <?> 04 <число экземпляров>` (668 в позднем сохранении) — всё, чем
Талион «владеет» как записями `Inventory/Items`, с количеством:
- `PC_Mirian` — мирианы (9 333 371);
- `Runegem_<цвет>_<вид>_<1Base…5Wondrous>` — самоцветы на складе по цветам и уровням
  (например, `Runegem_Red_Dmg_5Wondrous` — 792);
- `Primary_*` — образцы снаряжения (последнее число — сколько экземпляров этого образца в инвентаре);
- `PS_*_UNLOCK/_SKILL/_DUMMY`, `S_*`, `ScriptedUnlock_*` — навыки и способности;
- сюжет и мир: `GP_*Complete`, `*_FortOwned`, `*_Tower_*`, `*_Barrows`, `ShadowWar_Year*Complete`,
  `Outpost_*Complete`, `TribeFight_*`, `Gauntlet3_*`;
- коллекции и обучение: `Apdx_*`, `Col_*`, `Tutorial_*`, `Hint_*`.

Для NG+ этот список можно переносить выборочно, по префиксам записей.

### Таблица Cheat Engine `shadowofwar_seikur0_v21` (SeiKur0, 2017)

Работает с памятью запущенной игры, не с сохранением. Что из неё полезно:
- подтверждение хеш-идентификаторов (`PC_Mirian` = `0x23B603FB`, `MarkerList_Potential`, `Default_OrcRarity` …);
- категории базы, описывающие орков: `Faction/Traits/Marker` и `Faction/Traits/Picker` (особенности),
  `Faction/Tribes/Definitions`, `Faction/Roles/Definitions`, `Faction/Personalities`, `Combat/Tree` (класс),
  `Character/Models`, `Faction/AppearanceTags/Tags`, `Faction/Loot/NemesisGear`; все они встречаются в данных
  Немезиды в сохранении (`Picker_*`, `Marker_*`, `TribeDef_*`, `ClassMarker_*`, `PersonalityMarker_*`);
- устройство орка в памяти: уровень−1 `+0x4B8`, имя `+0x498`, состояние `+0x508/+0x510/+0x51A`
  (подчинён, телохранитель, мёртв; известны имя, сильные и слабые стороны), класс ИИ `+0x188`, племя `+0x328`,
  роль `+0x318`, личность `+0x270`, списки особенностей `+0x1B8` (Marker) и `+0x1E8` (Picker), раны `+0x138`;
- предмет в памяти: уровень `+0x24`, образец `+0x38`, облик `+0x40/+0x48`, свойства со значениями (float) `+0x78`;
- точки перехвата (AOB) для уровня орков, редкости при создании, добычи, траты мириан.

### Орки (Немезида) — первый разбор

В сохранении 542 записи орков. Каждая запись состоит из трёх частей:
1. **Состояние.** Порядковый номер, 8 байт, имя (токен `08` — ключ текста `OrcNameGen1st_*`/`OlogNameGen1st_*`,
   числа вида `0x2252xxxx`/`0xC2EFxxxx`), `InvasionFaction_*`, регион `Faction_<регион>`, класс ИИ `AI_*`,
   место в иерархии `<регион>_Row_Overlord|Warchief|Captain_N`, затем число и список надетых вещей
   (оружие, части доспеха с обликом).
2. **Строка-идентификатор** `<32 hex>_NPC_<n>`.
3. **Описание.** Затем 8 байт, `04 N`, …, уровень − 1 (два раза; Зука Башня: 36 → в игре 37). Дальше идут:
   - `Role_*` — прозвище, текст `Orc_Title_*`;
   - `TribeDef_*` — племя;
   - список `Marker_*` (редкость, потенциал, скорость обучения, специализация, класс, личность);
   - список `Picker_*` — особенности; текст берётся из `Faction/Traits/Definitions`, поле `+0x3C` — ключ `IntRes_*`;
   - `Traits_*`, модель, облик `AD_*`, цвета, метки облика `Tag_*`, `TraitLevelOffset_*`.

То же число `0x2252xxxx` в записи предмета — имя прежнего владельца.

**Таблицы орков (2026-10-21).** В `WHDC` несколько таблиц по режимам: `00 InvasionGame | 0c 1 | 04 N | …`,
`00 Demo | 0c 1 | 04 27 | …` (27 орков-заготовок, одинаковы во всех сохранениях), `00 MainGame | 0c 1 | 04 N | …` —
основная игра. Запись орка: `0c 01 | 04 <номер> | 09 <8 байт> | 08 <имя> | 00 Faction… | …`, конец — `… 0 | 02 <n> |
00 <роль в поселении: Captain / FD_InvCap_20 / … или 0>`. **Номер орка = его место в `MainGame`**, номера идут подряд
0…N−1, заголовок `04 N` = число записей (пройденная игра 500, пролог 196). Новый орк дописывается в конец с номером N,
заголовок +1 (проверено: смерть капитана Кирит-Унгола → новый №196 сразу на `MtnPass_Row_Captain_1`, `MainGame`
196 → 197). Мёртвые остаются на своих местах (строку `_NPC_` у старых мёртвых игра убирает: 500 записей, 408 строк).
При появлении орка меняются также: номер на посту крепости (`FortAssault`/`Location` → номер орка), счётчик выдачи
титула (`Role_<титул> 04 n`), веса генератора классов (`AdvancedClass_* 0a`). В конце записи 9 чисел `08`: 7-е и 9-е
похожи на игровые отметки времени (9-е растёт на 1 у орков других регионов, 7-е < 9-е); у нового — 7-е = −73, 9-е = 14.

**Уточнение (2026-10-21, `research/orcs2.py`).** Раздел состояния: `04 <номер орка> | 09 <8 байт> | 08 <имя> |
00 Faction_<регион> или InvasionFaction_* | 00 Faction_<регион> | 00 AI_* | 00 <место в иерархии> | …`, затем
надетые вещи (`02 n | 04 -1 | 04 1 | 02 0 | <вещь> | 0 | AD_<облик> | 0c 1 | 0c 0 | 04 0 | 04 0 | 05 | 05 | 0f ''`),
затем строка `_NPC_`. Место в иерархии — `<регион>_Row_Overlord|Warchief|Captain_N`; **0 — места нет** (орк «в пуле»).
В описании (после `_NPC_`) первый `05` — флаги, среди первых чисел `04` четвёртое — **уровень − 1** (Зука Башня 36
→ 37, Бубол 31 → 32, Накра 48 → 49). В пройденной игре: 408 орков, 228 живых, 84 последователя, 75 живых врагов
без места (среди них сюжетные: Бруз — `AI` = `GP_Bruz`, назгулы и Король-чародей — племя `Sauron`, «Избранные»
без племени из заданий).

Проверено по экрану игры (Зука Башня, легендарный командир племени Ужаса, ур. 37, правитель Кирит-Унгола):
- «Неуязвимость» — `Resist_*_Immune`;
- «Уязвимости» — `Resist_*_Vulnerable`;
- страхи — `Fear_*`;
- «Советы» — часть `Resist_*_Resistant` (дальний бой, казни, огонь; яд, скрытность и холод при этом не показаны);
- «Классовые качества» — `BaseStrength_*`, `TribeAttack_*`, `Summoner_*`, `DyingCommand`;
- «Бонусы» — `ET_*` (высшие качества), `Curse_Weapon`, `HasGang_*`;
- «Проклятый» в титуле — метка `Marker_StatusEffect_Curse`.

Значение после каждой особенности (`00 0`) у всех орков одинаковое — признак видимости хранится не там.

### Возвращение орков после смерти — опыты

1. Флаг `CanResurrect` у 83 мёртвых врагов → игра сняла его у всех при загрузке (оставила у 9, у которых он был до этого).
2. Флаг у 17 мёртвых капитанов, лежащих трупами в своих слотах иерархии → игра снова сняла все.
3. Бубол Крушитель (флаг поставлен самой игрой) вернулся сразу при входе в его регион: уровень 32 → 79 (подогнан
   под Талиона), новый титул по ране («Столбняк»), реплика про изуродованное лицо, флаг снят, появился `IsNew`.

Причина: у Бубола, кроме флага, было запланированное событие. В очереди событий Немезиды (рядом с таймерами
`*_Cooldown`, `ContextAmb_*`) была запись `0c 01 | Faction_volcano | CheatDeath_Ambush | Faction_volcano | 04 384 |
08 0x199 | 04 10101`. Остальные записи очереди имеют вид `… | 00 0 | 04 -1 | …`. Число 384, видимо, указывает на орка
(не порядковый номер записи — у Бубола это 317). Для возвращения нужно добавить такую запись — это следующий шаг.

Опыт 4: трём мёртвым капитанам Минас-Моргула (в слотах) поставлен флаг и добавлено событие `CheatDeath_Ambush`
(запись очереди — 32 байта; счётчик очереди +3). Пересчитаны размеры: блок `WHDC` (оба поля), длина первого
раздела (u32 по смещению `0x15BE`, перед первым внутренним `SAVE`), общий размер в заголовке (`0x0C` и `0x10`
= длина данных − 0x14). Игра загрузила файл без ошибок — способ правки со вставкой рабочий. Но при загрузке
игра удалила все три события и сняла флаги: она проверяет что-то ещё. Номер орка в событии — число `04 N`
перед именем в разделе состояния (у Бубола 384).

Опыт 5 (ожидает проверки): к флагу и событию добавлена «награда за воскрешение». У Бубола в ожидании возвращения
в конце описания был список `04 1 | 00 ResReward_PinnicleScar_RazorJaw` (после возвращения — `04 0`). Записи
`ResReward_*` (73 шт.) — то, что орк получит при возвращении: шрам (`PinnicleScar_*`), страх, ненависть, смену роли.
Определение `Faction/Ambush/Definition` → `CheatDeath_Ambush` ссылается на события `Resurrected_Presented` и
`Resurrection_PreSpawn_Ambush` и на шансы `Ambush_Always`, `CheatDeath_SameCombat_Cooldown`.

Опыты 5–9 (награда за воскрешение, разные орки) — вылет через 1,5–2 с после загрузки, всегда по адресу
`exe+0x178D171`. Это проверка типа значения при чтении (`and dword ptr [0],0`): ждали число (`04`), получили `00`.
Раскрутка стека по таблице `.pdata` показала, что падает не чтение орков, а блок `STOR` (последний блок первого
раздела, тег возвращает метод `mov eax,'STOR'`). Причина: в первом разделе есть второе поле длины — u32 по смещению
`0x1609` (перед блоком `IVGD`) = длина данных раздела без внутреннего заголовка, всегда `[0x15BE] − 0x47`. Оно не
обновлялось, буфер раздела обрезался на число вставленных байт, и конец `STOR` читался за границей.
Итого при вставке в первый раздел нужно править: размер блока (оба поля), `0x15BE`, `0x1609`, заголовок (`0x0C`, `0x10`).
Опыт 10: опыт 5 с исправленным `0x1609`. Вылета нет, игра сохранила флаги, награды и оба события `CheatDeath_Ambush`
(орки 421 и 423), но никто не напал. В событии игра поменяла поля: `08 409 → 416`, последнее число `10101 → 675`.
У обычных записей очереди последнее число убывает со временем (`General_Ambush_Zog`: 10438775 → 9954750 → 9840238),
видимо, это таймер в мс — у Бубола оставалось ~10 с. У олога 423 стоит флаг `SeveredHead` (обезглавлен), у 421 нет
`PresentedToPlayer`, который был у Бубола.
**Опыт 10 — успех.** Через 5–6 минут игры в Минас-Моргуле (подчинение капитана, бои с рядовыми) пришёл Накра
Надёжный: уровень 81, «Получен новый титул: Накра Железный Череп», реплика про ноющий череп. После встречи в его записи:
роль `Role_Faithful → Role_IronSkull` (титул из награды), список наград пуст (награда израсходована), уровень 48 → 80,
число после метки времени `i4 → i8`, флаги `IsDead`/`CanResurrect` остались, событие удалено. Событие обезглавленного
олога 423 игра не выполнила, а перенесла: `T416 → T434`, таймер `675 → 11742`. Рецепт возвращения: флаг `CanResurrect`
+ событие `CheatDeath_Ambush` + запись `ResReward_*` + верные длины (включая `0x1609`).
Опыт 11 (не понадобился): из сохранения после опыта 10 убрано событие олога 423 (счётчик очереди 8 → 7),
таймер события 421 (Накра Надежный) обнулён, ему добавлен `PresentedToPlayer`.

#### Возвращение орка — рецепт по байтам (проверено опытом 10)

Всё — в блоке `WHDC` первого раздела (орки и очередь событий Немезиды). Разбор токенов — `research/tok2.py`,
поиск записей орков — `research/orcs.py`.

1. **Найти орка.** Раздел состояния начинается с `04 <номер орка>` (у Накры 421, у Бубола 384), затем `09 <8 байт>`,
   `08 <ключ имени>`, `00 InvasionFaction_*`, `00 Faction_<регион>`, `00 AI_*`, `00 <регион>_Row_*`. Дальше строка
   `0f <len> <32 hex>_NPC_<n>` и описание.
2. **Флаги.** Первый токен `05` (u64) в описании после строки `_NPC_`: поставить `IsDead` (бит 2) и `CanResurrect`
   (бит 4); у удачного опыта были также `PresentedToPlayer` (5) и `IdentityPresented` (7). Обезглавленные
   (`SeveredHead`, бит 17) не возвращаются — игра лишь переносит их событие.
3. **Награда.** В конце описания, перед рангом: `0c 01 | 04 0 | 0c 00 | 04 N | (00 ResReward_*) × N | 04 0 | 00 0 |
   02 2 | 00 Captain`, затем `0c 01 04 <номер следующего орка>`. Вставка: `04 0` → `04 1` и 5 байт `00 <хеш
   ResReward_*>` (например `ResReward_PinnicleScar_IronSkull` — титул «Железный Череп», реплика про череп).
   Награда определяет новый титул и реплику; после возвращения игра её расходует (список снова пуст).
4. **Событие.** Очередь событий: счётчик `04 N` стоит прямо перед первой записью; запись — 32 байта
   `0c 01 | 00 Faction_<регион> | 00 CheatDeath_Ambush | 00 Faction_<регион> | 04 <номер орка> | 08 <метка> | 04 <таймер мс>`
   (номер орка — смещение +18, таймер — +28). Вставить запись к остальным и увеличить счётчик. Найти очередь
   проще всего по записи `General_Ambush_Zog`. Метку можно взять как у Бубола (`0x199`); игра её перезаписывает
   (`409 → 416 → 434`) — вероятно, номер игрового «дня».
5. **Длины:** блок `WHDC` (оба поля), `0x15BE`, `0x1609`, заголовок (`save.fix_lengths` в движке).

Таймер идёт только во время игры (не в меню): обычные таймеры за 5–6 минут игры уменьшились примерно на 4,3 минуты.
С таймером 10 101 мс Накра пришёл через ~5–6 минут в своём регионе. Если вернуть орка не удалось, игра не удаляет
событие, а назначает его заново с новым таймером. После второй смерти флаги `IsDead`/`CanResurrect` остаются,
событие удаляется — без нового события орк больше не придёт. Уровень вернувшегося подгоняется под Талиона
(48 → 80 у Накры, 32 → 79 у Бубола).

Не проверено: возвращение орка без места в иерархии (у Мозу из опыта 9 вылет был из-за длины, не из-за награды)
и путь через «пул» — живые орки без места, которых игра сама продвигает на свободные места.

#### Прежний владелец на предмете

В записи предмета: `… 00 NG_<запись> 00 <0 или NemDes_*> 00 Role_<роль> 04 <ключ текста имени> 04 0 …`. Имя —
текст по этому ключу (тот же, что `08` у орка), титул — ключ текста в 10-м поле записи роли
`Faction/Roles/Definitions` (например `Role_WebBreaker` → `GearChallenge_MtnPass_CharRole_01` = «Паутинорез»;
у обычных ролей — `Orc_Title_*`). Так получается «Тарц Паутинорез», как в игре.

Ссылки базы `(G << 20) | индекс`: G — номер в общем списке из 2742 списков (категории и `_Structures*`),
упорядоченном по хешу имени; найдено 2729, поэтому G расшифровывается с поправкой (≈ +2 в начале, +10…+13 к концу).

## Перенос в новую игру — первая попытка

`research/ngplus_build.py` (черновик; пути к файлам и вспомогательные модули из `research/` пока жёстко прописаны,
нужны распакованные `game.gamedb`, `string.strdb` и `ShadowOfWar.exe`) собирает сохранение из прологового и позднего:

- `PPDC` — уровень − 1 и опыт копируются из позднего сохранения.
- `IVMG` — внутри вложенный кусок (токен `10` = u32 длина + байты), игра разбирает его позже. Его начало:
  `05 <две u32> | 00 PlayerSkin | 04 следующий номер экземпляра | 04 ёмкость таблицы запасов`, затем ячейки таблицы
  (`0c 01 00 ключ 04 количество 04 ? 04 n <n номеров экземпляров>` или пустая `0c 00`), затем таблица предметов,
  экипировка, самоцветы по слотам (`Socket_* → Runegem_*`). Таблица запасов собирается заново: записи пролога
  без предметов + из позднего навыки `PS_*` (кроме сюжетных), все записи с предметами, `Runegem_*`, `Has_*`, `PC_Mirian`,
  престиж. Остальное (предметы, экипировка, самоцветы) — из позднего целиком; `Talion_Isildur_Ring` заменено
  на `Talion_Celebrimbor_Ring`.
- `IVPD` — простой список `ключ → число`; к записям пролога добавлены навыки `PS_*` из позднего, кроме сюжетных.
- Сюжетные навыки: семейства, для которых в позднем сохранении есть `ScriptedUnlock_SkillGrant_*`
  (подчинение, удар из тени, угроза смертью, «хуже смерти», телохранитель, призыв, воскрешение мёртвых, глефа,
  двойной прыжок, способности Келебримбора и т. п.) — 21 навык из 106 не переносится.
- Мир, сюжет, крепости, коллекции, энциклопедия и обучение остаются прологовыми.
- Длины: блоки, `0x15BE`, `0x1609`, заголовок.

Проверка в игре (попытка 1): сохранение загрузилось с первого раза; уровень 69, опыт, мирианы, надетое снаряжение
(меч 70, кинжал 69, лук/доспехи/плащ 68) и навыки на месте; при загрузке игра ничего не удалила. Сюжетные навыки
в меню помечены «не хватает очков», а не «заблокировано». Софтлок: в задании первого акта нужно вставить самоцвет
в меч, а слоты уже заняты перенесёнными самоцветами. Самоцветы в слотах хранятся в конце `IVMG`:
`0c 01 04 8 | 00 Socket_X (0c 00 | 0c 01 00 Socket_X 00 Runegem_Y) …`; в прологе все слоты пустые.
Теперь сборщик освобождает все слоты (`research/sockets.py`), самоцветы остаются в запасе.

### Башни (найдено слежением за сохранением, захват башни Кирит-Унгола)

По 3 башни в 5 регионах: `MinasIthil` (Минас-Моргул), `MtnPass` (Кирит-Унгол), `SnowMtn` (Серегост),
`Volcano` (Горгорот), `Island` (Нурн). Захват одной башни меняет:
- таблицу запасов IVMG и IVPD: запись `<регион>_Tower_0N` (N = 0…2) со значением 1;
- `PDCC`: счётчик `TowerPurify_<регион>` +1 (записан дважды; 3 — все башни региона);
- `IIUC`: признак `SeeingStone_<регион>_0(N+1)` 0 → 1 — башня `_Tower_0N` соответствует камню `_0(N+1)`
  (захват `MtnPass_Tower_01` включил `SeeingStone_MtnPass_02`; в Минас-Моргуле `Tower_01` ↔ `SeeingStone_02`).

**Первый акт пройден** — запись `Blade10Part25` в `QSTD` = 1: включается один раз в конце первого акта и больше не
меняется (проверено на 205 копиях прохождения; пролог — 0, обе опоры начала второго акта и пройденная игра — 1).

Остальные изменения при захвате (`PDIC` — положение Талиона, `WHDC` — таймеры Немезиды) к башне не относятся.
`SeeingStone_Island_02` = `0x07499A43`: строки с этим именем в базе нет, в сохранении он виден только как хеш.

**Блок `IIUC`** (по порядку): `04 16` и 16 признаков `00 SeeingStone_* 0c 0/1` (ещё `_base`); `04 5` и пять
загадок дверей могильников `DoorPuzzle_<регион> 04 6 …` (выбранные слова); затем **список того, что показано на
карте и ещё не подобрано**: `04 N | (04 <запись> 0c 1) × N | 04 <счётчик>` — записи `Col_GondorPickup_*`
(гондорские артефакты), `Col_SpiderPickup_*` (воспоминания Шелоб), `Col_Lore_DoorClue_<регион>_*` (итильдин —
слова для дверей), `<регион>_Barrows_Pickup_*`, `GP_Fake_Barrows_Pickup_*`; дальше — предметы, лежащие в мире.
Осмотр местности с башни добавляет записи в этот список (19 → 23 → 28). Подобранное из списка убирается и
появляется в таблице запасов как `Col_*` (в пройденной игре: 63 в списке, 49 подобрано, пересечения нет).
Найденный вход в могильник — запись `<регион>_BarrowsIdentified` в таблице запасов.
При переносе башен признаки `SeeingStone` есть, а список показанного — нет: башня захвачена, но карта вокруг пуста.
Первая башня региона при подходе к ней всё равно проигрывает ролик захвата (перемещение и смена времени
работают и до него) — замечено пользователем, исправлять не нужно.
В пройденной игре все 15 башен захвачены, в чужом сохранении начала второго акта — Минас-Моргул и Кирит-Унгол.

## Данные игры, которые использует программа (`app/engine`)

- **Распаковка архивов:** на Windows — библиотека самой игры `oo2core_5_win64.dll` (функция `OodleLZ_Decompress`),
  она понимает и `8C 02`. На Linux — `ooz` (powzix/ooz, собран как `libooz.so` с экспортом `ooz_decompress`,
  путь в `OOZ_LIB`), `8C 02` не умеет. База и русские тексты лежат в `hotchunk.arch06`, там только `8C 06`.
- **Таблица опыта:** запись `PlayerPowerLevelCost` (`Combat/Stat/Constant/FloatArray`), числа float с +12,
  индекс = уровень − 1 (69 → 93 090; 80 значений).
- **Дерево навыков:** ряды меню `MenuTreeBase` `SkillRow1_Sword` (Бой), `SkillRow2_Dagger` (Разбой), `SkillRow3_Bow`
  (Дальний бой), `SkillRow4_Armor` (Призрак), `SkillRow5_Cape` (Наездник), `SkillRow6_RingWraith` (История) →
  узлы `MenuTreeNode/Skills` → навык `Inventory/Skill/Skills` (`PSS_*`) и улучшения `MenuTreeNode/SkillChild`.
  `PSS_X` ↔ `PS_X_UNLOCK` по имени, исключения — `PSS_TO_PS` в `gamedata.py`. Счёт «21/23» совпадает с игрой,
  если: считать изученные `_UNLOCK > 0` (часть навыков отмечена только в таблице запасов IVMG), не считать престиж,
  узлы «Воскрешение мёртвых» и «Тёмный Талион» показывать только когда что-то изучено.
- **Название и описание навыка:** `PSN_*` / `PSD_*` (тот же суффикс) через `Inventory/UIItemData` (`PSUID_*`).
- **Предмет:** название `UI_<образец>_N`, описание `UI_<образец>_D`, строка редкости «Легендарное » +
  `UI_LegendarySetName_<племя>` («Племени Мясорубки», «Вендетты»…), особое свойство легендарки — `UI_<SetProp>_D`,
  бонусы комплекта — `UI_LegendarySet_<племя>_Affix1_D` (2 предмета) и `_Affix2_D` (4); у «Вендетты» ключи `Bounty`.
  Строка «Комплект: снаряжено {1}/{2}» — отдельный текст. Значения («X%»), урон и здоровье в сохранении не хранятся.
- **Самоцветы:** `UI_Runegem_<цвет>_<тип>_<ступень>` («Безупречный самоцвет воина»). Слоты в конце IVMG — по одному
  на вид снаряжения (`Socket_1Sword` … `Socket_6Ring`), не на предмет. Открытие слота в игре стоит мирианы.
- **Steam:** реестр `HKCU\Software\Valve\Steam\SteamPath`, библиотеки в `steamapps\libraryfolders.vdf`, игра —
  `appmanifest_356190.acf` → `installdir`; сохранения — `userdata\<аккаунт>\356190\remote\*_ShadowOfWar.sav`.
